# Session-Manager-GUI 使用手册

> DeepSeek Harness **独立插件** `Session-Manager-GUI`（当前版本 **0.1.6**）：
> WebUI 可视化操作 —— 会话行菜单“删除会话”、设置页“会话回收站”“已归档会话”与
> “常规不可见会话”；0.1.6 起删除/恢复按**父子绑定**连带子代理会话，回收站并标注
> 哪些条目是子代理。
> 与另一独立插件 `session-editor`（聊天工具）**可同时安装、互不冲突**。
> 版本针对 **DeepSeek Harness 0.1.5-rc.2、web profile**（0.1.2 起为 0.1.5-rc.1
> 适配版；0.1.5 与 0.1.6 均已复核 0.1.5-rc.2：两处被补丁产物与 rc.1 逐字节相同）。

---

## 0. 两个插件的关系（先读这段）

| | session-editor | Session-Manager-GUI（本插件） |
| --- | --- | --- |
| 定位 | 聊天内工具 | WebUI 可视化操作 |
| 提供 | `session_editor_list` / `session_editor_restore` / `session_editor_delete` | 会话行菜单“删除会话”；设置 → “会话回收站”“已归档会话”“常规不可见会话” |
| 版本线 | 独立 | 独立（**0.1.6**） |
| 删除语义 | 聊天工具 = 永久删除 | GUI = 软删除进回收站 |

两者没有同名工具、没有同名行 id、没有路由冲突，**可以同时启用**；
本插件的 GUI 操作不依赖 session-editor 是否安装。

## 1. 功能一览

| # | 功能 | 位置 | 行为 |
| --- | --- | --- | --- |
| 1 | **删除会话**（第 4 个菜单项，带垃圾桶图标） | 会话行右侧三点菜单（重命名/分叉/归档 下方） | 移入**回收站**（会话目录移出持久化扫描区，文件保留） |
| 2 | **会话回收站**（垃圾桶图标） | 设置（齿轮）→ “会话回收站”（Agent 预设下方） | 列出被删除会话的标题；每行右侧按钮：**恢复会话** / **彻底删除**（弹出确认对话框，确认后不可恢复） |
| 3 | **已归档会话**（归档图标） | 设置 → “已归档会话”（回收站下方） | 列出已归档会话的标题；每行右侧按钮：**删除会话**（移入回收站）/ **恢复会话** |
| 4 | **常规不可见会话**（eye-off 图标） | 设置 → “常规不可见会话”（已归档会话下方） | 列出平时侧栏看不到的会话：子代理会话（区分“父会话仍在”/“遗留”）、空白会话、无归属会话；支持按组批量**彻底删除** |
| 5 | **父子绑定删除/恢复** | 自动 | 删除父会话时连带其**子代理会话**（多级派生）一并移入回收站；恢复时一并恢复。删除前会提示本次将影响的子代理条数（R3 文案）。派生的 fork **不会**被级联 |
| 6 | **回收站的子代理标注** | 会话回收站页 | 子代理会话条目在标题前带「子代理」标志（悬浮显示所属父会话 id），普通会话不带 |

> 项 4–6 为 **0.1.6** 新增；项 2 的删除/恢复行为在 0.1.6 起按“父子绑定”成对处理。

图标约定：菜单里的“删除会话”与设置里的“会话回收站”共用同一垃圾桶图标
（`IconTrashOutline16`）；“已归档会话”使用归档图标（`IconArchiveOutline20`）；
“常规不可见会话”使用**自绘的 eye-off 图标**（DSH 内核 70 个内置图标里没有任何
“眼睛/可见性”图标，故按内置风格自绘：16×16、`fill:none`、`stroke:currentColor`、
`stroke-width:1.25`、圆头，斜杠为几何缺口而非依赖底色）。
回收站行前的「子代理」标志使用 DSH 内置的 `IconAgentPresetOutline16`
（一节点分叉为两节点的层级图元）。
原生三项菜单图标不受影响。

## 3. 安装

### 3.1 全新安装

1. **停止 Harness**（在运行 `dsh web` 的终端按 `Ctrl+C`）。
2. **拷贝插件包**到 profile 模块解析链的 node_modules（与 `@deepseek-ai` 同级）：
   ```bash
   cp -r "<工作区>/DSHPlugins/Session-Manager-GUI/Session-Manager-GUI" \
         ~/.dsh/profiles/node_modules/Session-Manager-GUI
   ```
3. **登记插件行**：编辑 `~/.dsh/profiles/web/cordis.patch.yml`，保留已有
   `session-editor` 行（如有），追加（见 `install/cordis.patch.yml.example`）：
   ```yaml
   - insert:
       - id: Session-Manager-GUI
         name: 'Session-Manager-GUI'
   ```
4. **打 UI 补丁**（两处原生产物均无扩展点，只能最小补丁）：
   ```bash
   cd "<工作区>/DSHPlugins/Session-Manager-GUI"
   node install/patch-ui.js --status     # 先看状态：产物版本 / 校验和 / 是否已打 / 有无备份
   node install/patch-ui.js --dry-run    # 预览计划（校验锚点，不落盘）
   node install/patch-ui.js              # 落盘（首次会自动写同目录备份 备份_client.js）
   ```
   补丁内容（三个目标，均可 `--target` 单独操作）：
   - **menu**（浏览器侧）：会话行菜单追加“删除会话”（带垃圾桶图标）并派发
     `Session-Manager-GUI:delete` 事件；
   - **settings**（浏览器侧）：设置导航为 `session-trash` / `session-archived` /
     `session-hidden` 指定垃圾桶 / 归档 / 自绘 eye-off 图标（0.1.6 起为三分支，
     脚本可从 0.1.5 的双分支形态**原地升级**）；
   - **reference**（主机侧，非插件自身功能）：让 `@` 候选标签与侧栏一致地回退到
     “前代检查点标题”，否则投影缓存格式较旧的会话在 `@` 里显示成裸会话 id
     （详见 §3.4）。
5. **（建议）跑一次离线自测**：确认安装包与运行环境都没问题——它自建临时
   `$DSH_HOME` fixture、**不触碰任何真实会话数据**：
   ```bash
   node install/selftest.mjs      # 发布包内预期："131 passed, 0 failed"
   # 开发树上是 "124 passed, 0 failed, 7 skipped"（7 条为发布卫生检查，开发树不适用）
   ```
6. **重启并硬刷新**：`dsh web` → 浏览器 `Ctrl+Shift+R`。
   注：web profile 常挂 `client-hmr` 行（约 500 ms 轮询客户端产物 mtime/size，
   经 `/plugins/events` 推送 rebuilt 帧），因此**两个浏览器侧补丁**在正在运行的
   `dsh web` 上通常无需重启就会重新下发；**reference 是主机侧模块，必须重启
   `dsh web`** 才生效。硬刷新浏览器仍是最稳妥的确认方式。
7. **验证**：会话行“⋯”菜单出现第 4 项“删除会话”（带图标）；设置最下方
   出现“会话回收站”“已归档会话”，图标分别为垃圾桶与归档。

### 3.2 从旧插件 `session-editor-gui` 迁移（原地升级）

本插件由 `session-editor-gui` 改名而来，安装方式如下：

1. 停止 Harness；
2. 编辑 `~/.dsh/profiles/web/cordis.patch.yml`：删除旧行
   （`id: session-editor-gui`），按 3.1 第 3 步追加新行；
3. 删除旧包目录 `~/.dsh/profiles/node_modules/session-editor-gui/`，按 3.1
   第 2 步拷入新包；
4. 运行 `node install/patch-ui.js`：脚本检测到会话菜单里仍是**旧版补丁**
   时，会先从同目录备份 `备份_client.js` 恢复原版、再打新补丁（设置导航
   补丁为首次打）；
5. 重启 + 硬刷新，按 3.1 第 6 步验证。

### 3.3 Harness 升级后重打补丁（rc.2 适配流程）

**为什么会掉**：`~/.dsh/profiles/node_modules/@deepseek-ai/*` 是指向 npx 部署目录
（如 `~/.npm/_npx/<hash>/node_modules/@deepseek-ai/`）的**符号链接**，
npm 升级会重写真实文件——被补丁的产物与同目录备份 `备份_client.js` 一起被清掉，
于是菜单里“删除会话”消失、设置导航回落成默认齿轮。插件本体（主机半面 +
浏览器半面）不受升级影响，无需重装。

**重打（一条命令）**：

```bash
cd "<工作区>/DSHPlugins/Session-Manager-GUI"
node install/patch-ui.js --status     # 1. 诊断：产物版本、校验和、是否已打
node install/patch-ui.js              # 2. 重打（产物仍是已知原版时直接可用）
```

> 三个目标一起重打：`menu` / `settings` 由 client-hmr 自动生效，`reference` 是主机侧
> 模块，需要**重启 `dsh web`**；只要不重启，`@` 候选标签仍是旧行为（不影响插件功能）。

**三种结果与对应处理**：

| `--status` 显示 | 含义 | 处理 |
| --- | --- | --- |
| `upstream: current bytes are a known original` / `patched: no` | 升级后是未打补丁的原版 | 直接 `node install/patch-ui.js` |
| `patched: yes` + `patch strips back to a known original` | 补丁健康 | 无需操作（浏览器硬刷新即可） |
| `upstream: not a known original` | 新版本改了这两处产物 | 先 `--dry-run` **看锚点是否仍命中**；命中则 `node install/patch-ui.js --adopt` 采纳新原版为基线并重打，未命中则需更新脚本中的锚点/补丁逻辑 |

`--adopt` 会把新原版的校验和记进 `install/baselines.json`（含 Harness 版本与时间），
之后同一产物按“已知原版”处理；它同时会提示复核上游改动——**若上游自己也加了
会话删除/归档入口，应当撤掉本补丁而不是叠加第二份**。

> 0.1.5-rc.2 实测：两处产物与 rc.1 **逐字节相同**（校验和未变），故无需改锚点，
> 直接重打即可；升级后 `client-hmr` 在约 1 秒内重新下发补丁产物（`/plugins/events`
> 的 graph rev 由 `7d29db…` 变为 `86eef2…`），无需重启 Harness。

### 3.4 `@` 候选显示成裸会话 id（UUID 字符串）

**现象**：在输入框敲 `@`，候选里若干条不是标题而是形如
`5c882a6f-6c87-4547-9b8e-030ff3ffe10e` 的裸 id；侧栏里同一个会话却显示正常标题。

**原因（DSH 上游行为，非插件缺陷）**：`@` 候选的标签来自
`@deepseek-ai/dsh-session-reference` 的 `projectedTitle()`——它**只认当前格式**的投影
检查点（`cachedSnapshot`）；而侧栏/会话列表那条路径（`dsh-api-session-controller`）用的是
`cachedSnapshot(...) ?? cachedPredecessorTitle(...)`，多了一个“前代检查点”回退。
DSH 升级时投影缓存域版本会提升，旧检查点记录里没有 `formatVersion`，于是：
侧栏能读出标题、`@` 读不出→回退成会话 id。**插件全流程只读该缓存、从不写**，与此无关。

**三种处理方式**：

| 方式 | 操作 | 说明 |
| --- | --- | --- |
| 打补丁（本工程默认已打） | `node install/patch-ui.js --target reference`，然后**重启 `dsh web`** | 让 `@` 与侧栏用同一条回退链；主机侧模块，不参与 client-hmr，必须重启 |
| 逐个打开一次 | 侧栏点开这些旧会话 | DSH 会在会话再次转冷时用当前格式重写检查点，之后 `@` 即有标题 |
| 直接清理 | 用本插件“删除会话/彻底删除” | 不需要的旧会话（如历史子代理会话）从 `@` 中彻底消失 |

**验证**：重启后敲 `@`，原先的裸 id 应变成标题；`--status` 中 reference 一行应显示
`patched: yes` 且 `patch strips back to a known original`。

### 3.5 删除“幽灵会话”（侧栏看不到的会话）

**哪些会话会变成幽灵**：

| 类型 | 侧栏可见性 | 说明 |
| --- | --- | --- |
| **子代理会话**（`origin: "subagent"`） | ❌ 永不显示 | 产品规则 `sessionVisible()` 里的 `origin !== "subagent"`——子代理只在父会话行上聚合成计数徽标；它们也不进任何工作区的 `sessionIds`，所以分组和“未分组”里都没有 |
| 空白会话（新建未发消息） | 仅当前打开时显示 | 产品行为 |
| 已归档 / 已在回收站 | ❌ | 分别见设置里的两个页签 |

但它们仍然**存在**（日志目录 + 投影缓存），而 `@` 候选来自主机侧会话列表（只排除自己），
所以会出现在 `@` 里——这就是“幽灵”。

**删除方式**（插件的删除路径本来就支持“无工作区归属”的会话，条目里 `workspaceId` 记为 `null`）：

```bash
API=http://127.0.0.1:3080/Session-Manager-GUI
# 1) 移入回收站（可逆：设置 → 会话回收站 → “恢复会话”）
curl -s -X POST -H 'content-type: application/json' \
     -d '{"sessionId":"<会话id>"}' "$API/trash/add"
# 2) 在 GUI 里点“彻底删除”，或直接调 purge
#    （不可逆：删日志目录 + 投影缓存 + 回收站记账）
curl -s -X POST -H 'content-type: application/json' \
     -d '{"sessionId":"<会话id>"}' "$API/trash/purge"
```

> **旧格式 id**：2026-09 之前创建的会话 id **没有 `session-` 前缀**（形如
> `419c080d-16f3-4e0b-a871-a7f6ab9be02e`）。0.1.5 早期版本的 `checkSessionId()` 只认
> `session-…`，这些会话因此**根本无法通过插件删除**（一律 `INVALID_SESSION_ID`）——已修复：
> 现在两种形状都接受，路径安全校验（分隔符 / 前导点 / 纯 `..` / 长度上限）不变。
> 该修复属**主机半面**，需**重启 `dsh web`** 生效（`cordis-plugin-hmr` 行在 web profile 里
> 是 `disabled: true`，主机模块不会热重载）。

**⚠ 删除不级联**：删掉一个会话**不会**连带删除它派生的子代理会话——插件与产品都不做级联
（插件 `trashAdd`/`trashPurge` 都是单 id 操作；产品的 `archiveSession` 同样只针对一个 id）。
所以删掉跑过子代理的父会话后，这些子会话会继续留在磁盘上，成为**新的幽灵**（侧栏不显示、
`@` 里还在）。要清干净就需要按上面的方式逐个删除（id 可从 `@` 里拿，或见“子代理会话”一节）。

## 4. 使用说明与行为细节

### 4.1 删除会话（三点菜单）

- 软删除：**会话目录被移出 `$DSH_HOME/sessions` 持久化扫描区**（移入回收站存放区），
  因此侧栏列表、搜索与 `@` 提及候选都不再找到它；同时经归档集合隐藏（覆盖已打开
  的会话上下文），且**保留工作区槽位与全部文件**；
- 若会话**正在生成/执行**，主机拒绝并提示“该会话当前正在生成/运行中”；
- 删除后列表通常即时刷新；极端情况刷新一次页面即可。

### 4.2 会话回收站（设置页）

- 每行只显示会话标题（无标题显示“（无标题）”占位）；
- **子代理标注（0.1.6）**：若该条目是**子代理会话**，标题前会有一个带层级图标的
  「子代理」胶囊标签，鼠标悬浮可看到它属于哪个父会话（父会话 id）。判定依据是会话
  自身记录的 `origin === "subagent"`，因此**单独删除的、或恢复后再次删除的子代理也会
  被正确标注**（不只限于“跟着父会话一起删”的那些）；
- **恢复会话**：回到原工作区**原位置**；若会话原本在“未分类”下（没有工作区归属）
  则恢复到“未分类”；
- **原工作区目录已不存在时（0.1.6）**：恢复**仍然成功**——会话日志照常回到会话树，
  只是不挂回工作区分组，因此会出现在“未分类”下，`dsh web` 的日志里会打印一条
  带解释的警告。这是**有意为之**的降级：恢复的对象是会话日志，插件不会为了分组而
  伪造一个指向不存在目录的工作区记录，也不会去创建或删除你的工作区目录；
- **彻底删除**：点击后弹出确认对话框——“是否确认彻底删除？会话彻底删除后
  **不可恢复**。”（其中“不可恢复”为红色加粗 #FF0000），底部左侧“取消”、
  右侧“确认彻底删除”；点“确认彻底删除”才真正永久清除（日志目录 +
  投影缓存 + 工作区记账 + 归档成员 + 回收站记录）。对话框支持 Esc 或
  点击遮罩取消。
  若该会话页面仍开着（上下文未销毁），文件会立即擦除，界面记录先保持隐藏、
  待上下文关闭后由插件自动清扫——期间**不会**出现“未分组”幽灵行。

### 4.3 已归档会话（设置页）

- 每行显示标题；**恢复会话** = 取消归档（回原槽位）；**删除会话** =
  移入回收站（可再恢复/彻底删除）；
- 归档页自动排除回收站中的会话，避免两处重复出现。

### 4.4 常规不可见会话（设置页，0.1.6 新增）

集中列出**平时在侧栏看不到、但真实存在**的会话，分三组：

| 分组 | 内容 |
| --- | --- |
| **子代理会话** | `origin === "subagent"` 的会话。再细分两档：**父会话仍在**（父会话还活着）与**遗留**（父会话已不存在）。每行标注是否运行中 |
| **空白会话** | 从未产生过对话内容的会话 |
| **无归属会话** | 不属于任何工作区、也不在回收站/已归档里的会话 |

页首有统计行（条数、占用字节、运行中条数），按 `createdAt` 倒序排列，超过 200 条会显示
截断提示。每组带「彻底删除本组（N 条）」按钮：点击后弹确认框并**列出条数 + 标题清单**
（最多 10 条，其余显示“…等另外 N 条”），确认后逐条**彻底删除**（不可恢复）。

**为什么需要这一页**：子代理会话**永远不会出现在侧栏**（产品规则：
`sessionVisible = origin !== "subagent" && …`，它们只在父会话行上聚合为计数徽标），
而 `@` 的候选来自主机侧实时列表、照样能搜到它们。于是就会出现“`@` 里搜得到、
工作区与回收站里都找不到”的“幽灵会话”。本页就是它们的统一管理入口。

### 4.5 与 session-editor 聊天工具的分工

- `session_editor_delete`（聊天工具）语义：**永久删除**；
- GUI 的“删除会话”是**软删除（进回收站）**；
- 对已进回收站的会话使用聊天工具永久删除，会留下失效的回收站记录（之后
  “恢复”会报日志不存在，“彻底删除”可清掉该记录）。建议先“恢复”再操作。

## 5. 数据与安全说明

- 回收站数据：`~/.dsh/storages/session_trash.json`（原子写入）；
- 主机 API：同源前缀 `/Session-Manager-GUI`（GET/POST JSON）。该路由是
  自定义裸路由，**无内置鉴权**——请仅在 Harness 绑定本机/可信网络时使用；
- 会话日志本体：正常位于 `~/.dsh/sessions/…`；软删除后移动到
  `~/.dsh/storages/session_trash/<sessionId>/`（**不删除**），恢复时移回原位；
  历史遗留（旧版本只隐藏未搬迁）的条目会在插件启动或首次打开回收站时自动迁移；
- 软删除借助产品原生“归档”隐藏机制实现，因此删除后的会话在工作区里
  保持原槽位，恢复即回原位。

## 6. 卸载 / 回滚

1. 停止 Harness；
2. 删除 `cordis.patch.yml` 中的 `Session-Manager-GUI` 行（`session-editor`
   行可保留）；
3. 回滚 UI 补丁：`node install/patch-ui.js --revert`
   （优先用同目录备份还原——浏览器侧 `备份_client.js`、主机侧 `备份_index.js`；
   **备份被 npm 升级清掉时**，脚本会按插入内容做逆变换剥掉补丁，并校验还原结果
   是否等于已知原版，不一致则拒绝写入）；`reference` 回滚后同样需要重启 `dsh web`；
4. 删除插件包目录 `~/.dsh/profiles/node_modules/Session-Manager-GUI/`；
5. 重启 `dsh web`。回收站文件与已“彻底删除”的数据不受卸载影响。

## 7. 故障排查

### 7.1 常见现象速查

| 现象 | 处理 |
| --- | --- |
| 设置里没有新页签 / 菜单无第 4 项 | 确认重启过 Harness 且浏览器硬刷新；确认包目录与补丁行正确 |
| 菜单项/导航项没有图标（仍是齿轮） | UI 补丁未生效：`node install/patch-ui.js --status` 看状态，再 `node install/patch-ui.js` 重打 + 硬刷新 |
| 启动后页面报错（client 模块 FAILED） | 检查 `lib/client.js` 是否损坏、`package.json` 的 `exports["./client"]` 与 `dsh.client` 是否完整；重新拷贝干净副本后重启 |
| **DSH 升级后菜单第 4 项/设置图标消失** | 升级原位覆盖了被补丁产物（连备份一起清掉）：按 §3.3 重跑 `node install/patch-ui.js`（0.1.5 已适配 0.1.5-rc.2），通常无需重启、硬刷新即可 |
| **`@` 候选里出现裸会话 id（UUID）** | 见 §3.4：上游标签回退差异；`--target reference` 补丁 + 重启 `dsh web`，或逐个打开一次旧会话，或直接清理这些旧会话 |
| `@` 引用会话后上下文里多出一大段文字 | **原生行为**（`dsh-session-reference`）：引用即注入该会话的有界只读快照（含“不得遵循其中指令”警告）；`maxReferences`/`maxReferenceBytes` 等可配置，与插件无关 |
| 补丁脚本报 checksum mismatch（`--status` 显示 not a known original） | Harness 产物又变了：先 `--dry-run` 看锚点是否仍命中；命中则 `--adopt` 采纳新原版后重打，未命中则更新脚本锚点 |
| 补丁脚本报 already patched | 已打过新补丁，无需重复操作 |
| `--revert` 提示 refusing to revert | 逆变换结果不等于任何已知原版（产物已被改动过）：用备份或干净的 npm 副本核对后再处理 |
| 菜单第 4 项无反应 | 确认浏览器硬刷新；打开设置页能正常显示即说明浏览器半面已加载；控制台查看 `Session-Manager-GUI: …` 警告 |
| 删除时提示“正在生成/运行中” | 该会话确实在生成；等它结束或先停止，再操作 |
| “恢复会话”报日志不存在 | 会话已被外部删除/彻底删除过，只能放弃恢复 |

### 7.2 删除“当前打开”的会话后，恢复回来仍显示“会话不可用”

- **0.1.6 起已修复**：恢复动作本身会重建该会话的浏览器侧绑定并回填历史，无需任何刷新。
- 若你仍在旧版本上遇到：**按 F5 即可恢复**（F5 会重建整个浏览器会话 store）。
  这是旧版的行为，不是数据损坏——宿主侧一直是健康的，消息也一直正常落盘。

## 8. 已知限制

- 三处补丁作用于安装包内原生产物（两处浏览器侧 + 一处主机侧），**Harness 升级后
  需要重打**（§3.3）。升级同时会清掉同目录备份，因此升级后的回滚依赖脚本的
  逆变换路径；`reference` 为宿主模块，重打/回滚后需重启 `dsh web`；
- profile 的 `@deepseek-ai/*` 是 npx 部署目录的符号链接，补丁实际写在
  npx 部署目录的真实文件上（`--status` 会打印 realpath）；
- 菜单项文案固定中文“删除会话”（原生菜单词典不对外暴露注册口）；
- 包名 `Session-Manager-GUI` 含大写字母，符合本部署的 loader/client 扫描
  规则，但**不是合法 npm 包名**，不能用 `npm/pnpm add` 从 registry 安装
  （本插件设计为目录拷贝安装）；
- 本机多 Harness 实例共享 `$DSH_HOME` 时，回收站文件按单进程假定；
- 若自行开启了持久化全文检索库，彻底删除不清理其索引行（默认未开启）。

    丢弃被污染的 scope、显式材料化新 scope 并调用 `session.open()` 回填历史，带
    `[0, 1.2, 3, 6]s` 重试编排（每次幂等）。实测：恢复后约 1 秒历史回来、输入框立即可用。
  - **原工作区目录已不存在时，恢复仍然成功**：此前会因 `realpath` 抛 ENOENT 而报内部
    错误，并把刚搬回的日志又退回回收站（会话 header 里的 `cwd` 只是“记忆”，目录可能已被
    移动或删除）。现在改为：目录还在 → 原逻辑；目录没了 → **照常恢复日志**、跳过工作区
    分组、落到“未分类”，并在 `dsh web` 日志里打印带解释的警告。**不会**为不存在的路径
    伪造 workspace 记录。
  - **新增路径白名单守卫（两层）**：所有文件操作只允许作用于 `$DSH_HOME` 内的四类路径
    （`sessions/**`、回收站存放区、会话投影缓存、回收站索引）；第二层用 `realpath` 解析
    真实路径，阻断“符号链接父目录逃逸”。即使回收站索引被篡改也无法把删除指向工作区
    交付物——**插件绝不删除或写入任何工作区文件**。
  - **僵尸 Agent 修复**：删除会话时若只卸载会话上下文而未同步退役代理注册项，之后发给
    该会话的消息会进队列却**永不落盘、永无回应**，且 id 占位导致无法重新恢复。现在
    删除、级联删除、恢复、启动清扫四条路径都成对退役（`agent.cancel()` + 从 agents
    注册表移除）。
  - 自测从 97 条扩充到 **112 条**（新增：cwd 存在/消失两分支、回收站子代理标注与降级行为）。
